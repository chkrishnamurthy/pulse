What is in the app now

Screens, sync and widgets

Each screen matches the Pulse design canvas and works in light and dark mode.

Today

24-hour day dial (sleep arc + steps per hour), a daily insight against your own 30-day normal, cards you can switch on, off and reorder. Pull down to refresh.

Heart

Day / Week / Month. Heart-rate chart with shaded zones, resting heart rate against your normal, HRV, zone minutes.

Sleep

Stages through the night, time in each stage, SpO2, breathing rate, skin temperature, bedtimes this week.

Activity

Weekly zone minutes, distance, active time, and your workout history.

Trends

Week / Month / Year reports: steps and sleep bars against goals, resting heart rate trend, best day, longest sleep.

Goals and Settings

Change goals with + and −, units, System / Light / Dark, sync status with Sync now, delete local data, sign out. Every delete asks first.

Try it before signing inOn the welcome screen tap Look around with sample data. Every screen fills with example numbers and shows a "Sample data" banner, so you can judge the design right away. Home-screen widgets: long-press your home screen → Widgets → Pulse (Smart, Steps, Heart, Sleep, Sync).

Do this now

Open and run the app on your phone

No Google setup needed for this part. You will see the welcome screen, the themes and the menu. Sign-in will show an error until Part B is done, which is expected.

Open the project

  • Start Android Studio → File → Open → choose the folder D:\fitbit-track\android → OK.
  • Wait for "Gradle sync" at the bottom to finish (first time: a few minutes).

Turn on developer mode on your phone

  • Settings → About phone → tap Build number 7 times.
  • Settings → System → Developer options → turn on USB debugging.

Connect the phone

  • Plug in the USB cable. On the phone, tap Allow on "Allow USB debugging?".
  • Your phone's name appears in the device menu at the top of Android Studio.

Press Run (green ▶)

  • The Pulse app installs and opens on your phone.
  • Try the theme: turn your phone's dark mode on and off; Pulse follows it.
What you should seeWelcome screen with the dial logo and "Continue with Google". Tapping it now shows a "Developer error (10)" message. That is correct: Google does not know the app yet. Part B fixes it.
Part B · after Phase 2 Step 7

Let Google recognise the app

Do this only after the other session confirms test calls A to E worked. Android apps don't use a password or secret. Google recognises the app by two values: its ID and the fingerprint of the key that signed it.

Value 1 · package name
com.fitbittrack.pulse

Fixed for this app. Don't change it later, or you must redo this step.

Value 2 · SHA-1 of your debug key
0F:6F:83:92:E2:FD:99:DE:9D:FF:92:F7:FC:E6:47:7E:E3:9A:18:F7

Read from this PC's Android debug key. It is public information, not a secret. A release build later needs its own SHA-1.

Open Credentials in the same project

  • Signed in with your builder account, open console.cloud.google.com/apis/credentials.
  • Check the project picker at the top shows fitbit-tracker-515502.

Create an Android client

  • + Create credentials → OAuth client ID.
  • Application type: Android. Name: Pulse Android (debug).
  • Paste the package name and the SHA-1 from above → Create.
  • No file to download. Nothing to paste into the app.

Run the app again and sign in

  • Tap Continue with Google. Google's own screen opens.
  • Pick your Fitbit Google account (not the builder account), then allow all 5 permissions.
  • Today shows a green Connected pill when Google Health answers.
Not yet provenGoogle's Health API pages only show web-type clients. This app uses Google's Android sign-in (no secret, no browser tab). If Google refuses it for the Health scopes, we switch to the documented route: AppAuth with the system browser (Chrome Custom Tabs). Only GoogleHealthAuth.kt changes; the screens stay the same.
